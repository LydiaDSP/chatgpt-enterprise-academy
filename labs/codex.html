CODEX LAB · NO-CODE TO AI CODING

不会写代码，也能提出可验收的开发任务

Codex 不只是补几行代码：它可以协助你开发Python分析脚本、办公小工具、网页应用和业务工作台，也能参与现有系统重构、自动化测试与Agent开发。本页先看任务地图和开发方法，再用采购订单CSV工具完成一次真实演示。这里的浏览器工具是预置教学程序，不会伪装成Codex即时生成。

课堂建议 20–25 分钟 · 任务地图 + 开发方法 + 现场演示

二、不会编程，如何把需求变成软件？

你不必先学会一门编程语言，但要学会把业务问题讲清楚，并在关键节点确认需求、检查结果和验收成果。

STEP 01

说清问题

谁在什么场景遇到什么问题？现在怎么做？最想减少哪一步工作？

你要确认：真实需求与使用者
STEP 02

定义需求

让AI整理功能清单、输入输出、页面草图、业务规则和验收标准。

你要确认：范围、优先级和规则
STEP 03

制定计划

先阅读现有文件，给出技术方案和分步计划；确认后再开始修改。

你要确认：方案与修改范围
STEP 04

分步开发

先做最小可用版本，每次完成一个小功能，避免一次性开发过多内容。

你要确认：每个阶段的实际结果
STEP 05

测试验证

用正常、异常和边界数据测试，查看运行结果、报错信息和修复记录。

你要确认：测试证据，而非AI口头承诺
STEP 06

审查优化

检查功能是否符合需求，界面是否易用，是否存在数据、安全和权限风险。

你要确认：业务、IT与安全要求
STEP 07

交付维护

整理运行说明、依赖环境、版本记录、备份与回滚方式，再决定是否部署。

你要确认：谁使用、谁维护、谁批准
关键原则

先小后大

先完成一个能运行、能测试的小版本，再根据真实反馈逐步增加功能。

不要一开始就要求AI开发完整系统

我不是专业软件开发人员，请作为我的AI开发搭档，用业务人员能理解的语言带我完成这个项目。 我的目标：[描述希望解决的业务问题] 实际使用者：[谁会使用] 目前的做法：[现在如何处理、哪里耗时或容易出错] 期望结果：[希望得到什么工具、页面或自动化能力] 请按以下方式协助我： 1. 先向我提出必要的澄清问题，不要自行猜测业务规则。 2. 将需求整理成功能清单、输入输出、页面/操作流程和验收标准。 3. 先检查当前工作目录和已有项目，说明拟采用的方案、会新增或修改哪些文件；此阶段不要修改文件。 4. 等我确认后，再拆成小任务逐步开发，每完成一项就展示结果。 5. 实际运行程序和测试，提供测试输入、运行命令、结果与未通过项；不要只说“已经完成”。 6. 用非技术语言解释我需要知道的操作方法、限制和风险。 7. 未经我确认，不删除原文件、不覆盖业务数据、不连接生产系统、不部署或对外发布。

三、借助辅助项目，让 AI 按专业流程开发

这些项目不是新的编程语言，而是给 AI Coding Agent 增加开发方法、工作规范和专业角色。它们能帮助初学者少走弯路，但不能替代人的业务判断和最终验收。

优先了解 · Codex App / CLI 可用

Superpowers

一套面向 AI Coding Agent 的开发方法论和技能集合。核心是先讨论需求和设计，再形成细化计划，之后按步骤开发、测试和验证，减少AI跳过规划直接写代码的问题。

它会辅助哪些环节？

  • Brainstorming：通过提问澄清需求，形成设计说明。
  • Writing Plans：把工作拆成小任务，明确文件和验证步骤。
  • Test-Driven Development：先写测试，再实现和重构。
  • Code Review / Verification：检查改动并验证结果。

如何在 Codex 中使用？

  1. Codex App：打开左侧 Plugins，在 Coding 分类找到 Superpowers，点击添加。
  2. Codex CLI：输入 /plugins，搜索 superpowers，选择安装。
  3. 重新开始一个开发任务，先描述目标，让它带你完成需求梳理与设计，不要直接要求写代码。
适合：没有成熟开发流程、希望AI一步一步带着做的学员。安装后仍需确认每个阶段的产出。

进阶拓展 · Codex CLI 适配为实验性

GStack

Garry Tan 开源的虚拟软件团队工作流。它将产品、工程、设计、代码审查、QA和发布等视角组织成可调用的技能，让AI不只从“程序员”一个角度看问题。

可以体验的角色视角

  • 产品/CEO视角：重新审视用户问题和产品价值。
  • 工程负责人视角：梳理架构、数据流和技术风险。
  • 设计视角：检查交互流程和视觉体验。
  • Review / QA视角：检查代码改动、运行应用、复现问题。
  • 发布视角：整理测试、变更和交付步骤。

如何在 Codex CLI 中尝试？

git clone --single-branch --depth 1 https://github.com/garrytan/gstack.git ~/gstack
cd ~/gstack
./setup --host codex
./setup --status

安装后可尝试调用 gstack-office-hours，让AI先把一个业务想法梳理成设计方案，再体验工程评审、Review和QA等技能。具体技能名称以当前安装版本为准。

注意：GStack 对 Codex CLI 的支持目前标记为 experimental。需要 Git、Bun 等运行环境；Windows 还涉及 Node.js 等依赖。部分安全约束在该环境中是提示而非强制，不建议初学者直接用于生产项目。

四、什么时候用 Chat、Work，什么时候用 Codex？

工具适合处理典型任务
Chat讨论、分析、生成代码片段或解释技术概念解释Python报错、设计分析思路、生成一段公式或脚本供人工使用
Work跨文件、网页和应用的多步骤任务执行与交付整理多份文件、研究资料、生成报告、在授权应用中完成工作流程
Codex围绕项目目录和代码库进行软件开发创建脚本/应用、运行代码、测试、修复Bug、重构和维护项目
简单判断：只需要一次分析或一段代码，用Chat；需要跨文件和应用完成多步骤工作，用Work；需要持续创建、修改、运行和测试代码项目，用Codex。三者能力有交集，具体取决于工作区和授权配置。
