# SOP/SIP 版本变更审查

## 何时使用
当用户提供了两份可访问、已授权的 SOP、SIP、设备作业指导书文本或可解析的文件，并要求分析版本变化、参数改变和检验控制点时使用。不要把此 Skill 当作企业法规符合性认证工具。

## 输入与前置检查
1. 询问或从文件识别旧版、新版、文号、版本号、生效日期；无法确认时标注“待确认”，不得猜测。
2. 确认文件属于用户可访问资料；输入含个人信息、生产参数或客户信息时，遵从组织数据处理规定。
3. 检查文件是否可读、章节是否齐全；扫描件、图片表格和格式提取不完整时说明证据限制。
4. 首先确定比较范围。若只有部分章节可见，输出“仅比较已提供部分”。

## 执行步骤
1. 按文件章节或可追溯条款建立对应关系。记录旧版和新版的**原文引用位置**（页码、章节、行号或可定位标题）。
2. 识别以下变化：操作步骤；温度/压力/时间等工艺参数及公差；抽样数量与检验频次；合格判定标准；设备校准；记录保存；人员复核与授权。
3. 对于新增、删除、修改分别记录。对格式、排版或无业务影响的文字变化，独立分类。
4. 每项变化写出“旧版证据 → 新版证据 → 可能影响 → 需要谁确认”。没有明确证据时输出“待核实”，禁止补写未提供的数值。
5. **潜在风险是待验证假设**，不能把参数变更自动等同于质量不合格、法规不符合或应停机。
6. 对照本 Skill 的 [输出字段规范](references/output-schema.md) 生成完整差异表，再给一个最多6条的管理摘要。
7. 最后列出信息缺口、待复核/审批人员和复核清单。提醒用户遵循现有文件变更控制流程。

## 完成前的自检
- [ ] 已标明旧版、新版和比较范围
- [ ] 重要参数值及单位逐字核对，没有漏掉公差、单位或频次
- [ ] 重要结论均能追溯到旧版、新版的对应位置
- [ ] 对含糊、缺失和冲突之处明确标记“待确认”
- [ ] 变更类型与风险等级分别说明判断理由
- [ ] 保留人工批准环节，不擅自发布、生效或改写原文件

## 禁止动作与边界
- 不自动审批、替代QA签核、批准验证结论或改写受控SOP。
- 不提供对未验证生产设备的直接参数变更命令。
- 不虚构页码、标准号、法规要求或文件原文。
- 若差异证据不足，提交问题清单，而不是给出确定性质量判断。

## 输出格式
严格使用 [输出字段规范](references/output-schema.md) 中的变更表，并另附：
1. 文件与范围概览
2. 重点变化摘要（最多6条）
3. 差异清单（含证据定位）
4. 风险假设和验证任务
5. 待确认项与人工审批提示
