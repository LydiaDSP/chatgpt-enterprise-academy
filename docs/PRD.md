## 1. 项目背景与问题定义

### 1.1 业务背景

培训对象是制造业企业中使用 ChatGPT Enterprise 的跨部门员工，涉及财务（FIN）、研发（RD）、品保（QA）、供应链（SCM）、制造（MFG）、人资（HR），并补充 IE 与 IT 岗位场景。学员对 AI 的熟悉程度不同，有人只会简单问答，有人需要处理文件、数据、研究、代码与跨工具流程。

传统培训方案存在五个关键问题：

1. **PPT 被动听讲**：看得到能力名称，却无法在现场点击、练习、比较输入与输出。
2. **功能列表与工作脱节**：只介绍产品入口，学员难以理解实际岗位怎样操作。
3. **Prompt 教学过时或过长**：没有体现现代模型可通过简洁目标、必要上下文、迭代与校验完成任务。
4. **Chat / Work / Codex / Agent 概念混淆**：容易把“桌面端”误当“智能体”，或把模拟脚本误当自动化落地。
5. **教学不可复现**：缺少模拟数据、复制指令、执行步骤、预期结果、异常验证与验收证据。

### 1.2 产品定位

本产品首先是**供讲师现场使用的 120 分钟互动教学网站**，不是传统 PPT，也不是直接操控企业生产系统的平台。课后可作为员工长期查阅和练习的学习资源。

核心教学链路：

**认识能力 → 明确业务问题 → 选对工具 → 动手练习 → 复核证据 → 认识权限边界 → 从 Chat 走向可控自动化。**

### 1.3 核心目标

- **G1 教学**：讲师无需按传统 PPT 翻页，即可用网页完成一堂完整、层次清晰、可互动的 120 分钟课程。
- **G2 上手**：非技术学员能用企业版 ChatGPT 完成至少一个文件、数据、研究或岗位案例的可复现练习。
- **G3 分工**：学员能正确区分 Chat、Deep Research、Work、Browser/Computer Use、Codex、Skill、MCP、Plugin、CLI、Agent。
- **G4 复用**：每个重点案例都尽可能包含准备资料、操作步骤、可复制任务、输出样例、核验规则和升级路径。
- **G5 安全**：一切课堂互动明确区分“浏览器本地演练”与“真实 AI/企业系统执行”；真实操作须符合管理员策略和业务审批。
- **G6 可维护**：开发、内容和测试按模块拆分，有清晰的版本、需求编号和验收标准。

### 1.4 非目标

本阶段**不建设**企业级 LMS 学员后台、在线题库排名系统、企业生产系统网关、AI 推理后端、真实智能体调度平台、MES/ERP/WinCC 接口、企业数据中台或自动审批平台；更不允许通过静态网页擅自控制 PLC、设备、网络配置或人事/财务数据。

## 2. 用户、场景与角色

| 角色 | 主要目的 | 典型动作 | 设计要求 |
| --- | --- | --- | --- |
| **讲师（主角色）** | 120 分钟内高效演示与引导课堂 | 切章节、投影大字、展示讲师提示、带学员做课堂练习 | 快捷、视觉清楚、每步有时间和讲解要点 |
| **跨部门普通学员** | 以较低门槛学会当前可用的 AI 办公方法 | 复制 Prompt、下载模拟 CSV、做研究判断、复核结果 | 少术语、一步步操作、结果可检查 |
| **IE / IT 专业学员** | 先学 Chat 协作，再理解 Agent 化实现 | 看岗位案例、切 Chat/Agent、运行只读示例 | 具体字段、触发器、异常处理及审批 |
| **业务部门经理/审核人** | 判断案例值得不值得试、是否存在风险 | 看输入、产物、验收指标和权限门槛 | 不能把教学推演当已部署项目 |
| **课程维护者/开发 Agent** | 持续补充场景、内容与交互 | 查 PRD、改模块、运行测试、提 PR | 文件结构、变更范围、回归规则清晰 |
| **IT/信息安全审核人** | 保障公开发布与实机使用安全 | 检查数据、域名、外链、日志及授权 | 无凭证、无真实敏感数据、无隐含连接 |

**预设授课环境**：电脑浏览器（优先 Chrome/Edge）+ 投影/大屏 + 企业批准的 ChatGPT 测试账号；可离线备份全部课堂模拟练习。实际功能入口、权限及模型能力由企业工作区配置决定。

## 3. 已确认的产品决策（不得在改版中丢失）

| ID | 决策 | 约束与原因 |
| --- | --- | --- |
| D-01 | **采用在线/离线 HTML 互动教学，不改回传统 PPT 主体** | 讲师需要现场演示与学员交互 |
| D-02 | **讲师版为主，课后练习版为辅** | 游戏化更适合自学；不能干扰授课节奏 |
| D-03 | **保持三诺红视觉体系** | 原型和课件需统一、专业、适合投影 |
| D-04 | **Prompt 参考吴恩达《AI Prompting for Everyone》完整 M1/M2/M3** | 不只补充几个提示词套路，需覆盖研究、思考、多模态、分析、构建与综合项目 |
| D-05 | **提示词简洁、可迭代，突出“任务/上下文/标准/验证”而非模板堆砌** | 适应当前模型能力，不鼓励无意义长 Prompt |
| D-06 | **主课覆盖 Codex AI Coding 实际演示** | 不能只有 Chat 或泛泛介绍 Agent |
| D-07 | **补充 AI 使用小技巧** | 包含截图、追问、文件、验证、上下文等高频技巧 |
| D-08 | **原 Excel 对应 30 条场景保留，按部门陈列，不设额外的场景筛选器** | 重点在“这个工作如何做”，而非堆标签筛选 |
| D-09 | **IE/IT 新增 6+6 条岗位扩展案例** | 这 12 条为教学拓展，不得冒充原 Excel 需求 |
| D-10 | **IE/IT 每案用互斥标签区分 Chat 与 Agent** | 阶段一：Chat 人工协作；阶段二：Agent 流程自动化，两个面板不混堆 |
| D-11 | **Agent 不等于桌面操作** | Agent 是受控自动化工作流；Computer Use 只是可能的执行手段之一 |
| D-12 | **Agent 方案必须可操作** | 明确 MVP、触发器、数据来源、字段、技术路线、六步流程、异常处理、人工审批、验收 |
| D-13 | **示例可复制且尽量可运行** | 给出模拟数据、脚本、期望数值及核验步骤 |
| D-14 | **并行开发互不覆盖** | Prompt Lab 与其他实验室分支独立推进，每批验收后再合并 |
| D-15 | **静态教学演练不伪装成真实 AI 执行** | 没有 AI API、后台、生产接口；所有预设答案、模拟日志、评分必须标注真实性 |
| D-16 | **公开仓库须做信息安全审查** | 不上传真实内部 Excel、员工资料、IP、设备日志、业务系统凭证等 |

| 38–55 | Work · Computer Use | 体验Agent多步骤执行与人工确认 |

**教学时间管理原则**：主课120分钟不增加。六大核心模块构成主线；AI效率技巧库和学习资源是辅助工具，不应与核心模块混为同级。Prompt M1/M2与M3完整素材属于专题素材池，课堂择要演示。正式授课前需冻结精确到分钟的讲师操作路线。

### 4.3 教师/学员双体验

- **讲师模式（主线）**：时间提示、讲解重点、课堂问题、可演示答案、回退路线、投影大字、快捷切章。
- **自学模式（现有）**：隐藏讲师提示，保留操作练习、任务复制、样例数据下载、本地“已学”标记。
- **游戏化课后练习（规划，不纳入现有主讲界面）**：任务挑战、闯关反馈、岗位路径、成就与复盘；不引入强制积分排行榜，不将“点过页面”当能力认证。
- **优先级**：先保证讲师版完整、准确、可控；后建设独立练习/游戏化体验。

**Prompt 内容与评分规范**

- **推荐 Prompt 骨架**：我想完成什么 → 当前已知事实/附件 → 约束与口径 → 希望输出什么 → 不确定或证据不足时如何处理。允许短提示起步，遇到失败再加信息，而不是一开始堆砌长角色设定。
- **结果不等于正确**：AI 输出须核对原始数据、适用版本、计算口径、来源和未解问题。
- **信息路径**：稳定常识优先直接提问；需要近期事实时结合可验证来源搜索；多来源对比、深入求证才考虑 Deep Research。
- **Rubric**：评分标准须可观察；优先事实依据，避免模型只迎合预设结论；客观结果需抽样或跨方法复核。
- **多模态**：图像“所见”与解释要分开；不得把教学脚本称为真实图像识别或真实生成结果。
- **M3 闭环示范**：模拟设备异常图 → 提取可核对信息 → 分析日报指标 → 形成排查培训或异常登记小工具 → 人工测试与回顾。

**Prompt 验收 AC-PROMPT**

- 六个 M1/M2 单元各自可以切换、操作、复制、显示正确的示范讲师提示。
- M1 五组对比与五道信息路径题均能复核；Deep Research 四步和来源辨识有明确理由。
- M2 上下文勾选影响复制内容；头脑风暴三轮衔接；Rubric 未满四维不得显示正式总分；大纲顺序变化影响输出任务。
- M3 五单元导航、进度、导出、空输入/损坏存储的恢复可用；模拟数据核算与来源 CSV 一致。
- 原有三类业务Prompt保留；MES数据分析归属M3，Deep Research归属M1；Work和Codex保持原功能。
- 实机打开 1920×1080 与 375px 检查，无重叠、遮挡；**真实模型反馈只在企业许可账号中验收**。

**三个容易混淆的维度**

1. **Chat vs Agent**：Chat 由人提出问题、准备输入并逐次核对；Agent 是可被事件/定时/人工触发的多步流程，具有数据接入、规则判断、审查、异常恢复和交付闭环。
2. **Work vs Agent**：Work 是面向完整目标的产品工作方式，可承载多步骤任务；它不等于已经实现了特定企业流程的长期定时 Agent。
3. **Computer Use vs Agent**：Computer Use 是在授权环境中对桌面界面进行操作的工具能力；Agent 完全可能通过 CSV、Python、只读 API、工单系统完成工作，**不要求桌面自动点击**。

### 6.3 IE/IT Agent 六步标准蓝图

1. **触发**：人工/定时/事件触发，写清时间窗口、业务对象、幂等键或批次号。
2. **取数**：使用已批准的只读导出或 API，保留来源、时间戳、版本、字段字典。
3. **清洗与规则计算**：验证缺失/重复/异常/单位与时间；确定性计算交给规则代码，不让 LLM 凭空算数字。
4. **智能辅助**：基于经过审查的摘要生成异常说明、建议和待核实问题；保留证据引用。
5. **人工审核与动作边界**：正式工单、数据写回、网络变更、设备控制、对外发送先走有权限的人工审批。
6. **交付与闭环**：保存结果版本、审查人、失败日志、复测差异和可量化指标。

**必须显式写出失败路径**：字段不全、设备 ID 不匹配、日志时间冲突、接口断线、报告同名、审批拒绝或观察窗口不足时停止/标记“待核实”，不能臆造结果。试点阈值由业务/IT 根据现场证据确定，不把教学数值直接应用到生产。

- 全部 Agent 案例都有可操作的六步蓝图，且复制出来的实施方案包含关键字段/权限/验收，而非一句“可接入 Agent”。
- 不出现真实员工、真实网络地址、账号、企业生产数据或承诺已部署的虚假描述。

## 7. 内容与交互设计规范

### 7.1 每个重点教学页的标准结构

推荐统一为：

1. **为什么学**：真实的岗位痛点或任务目标，不先介绍术语。
2. **能力分工**：这个问题该用 Chat、Deep Research、Work、Codex、Skill 还是规则脚本。
3. **准备资料**：提供模拟文件；真实数据只在授权工具和环境使用。
4. **讲师演示步骤**：具体点击/复制/观察什么，预估时间。
5. **学员互动**：选择、编辑、排序、复算、分步流程或运行本地工具。
6. **参考答案/验收点**：明确哪些能直接复算、哪些仍需人工判断。
7. **失败或危险示例**：模型幻觉、口径错、证据不足、超权限动作。
8. **迁移任务**：回到本部门实际工作时，需准备哪些合法数据/权限。
9. **回到课程主线**：不迷失在专题页面。

### 7.2 页面设计语言

- **配色**：沿用站点现有三诺红主题；当前主色约 #AA2737、深红约 #81202E、浅红约 #FCECEF；中性色正文、浅底与分隔线，避免大面积刺眼红色。
- **信息层级**：导航 → 章节标题 → 一句话学习目标 → 互动区 → 讲师提示/验证。减少大段纯文字堆积。
- **课堂优先**：按钮/问题/结果在投影下容易识别；完整内容允许折叠，不要求同屏展示全部术语。
- **可见反馈**：切换选项后相关指令/输出同步；复制、校验、完成、重置必须明确反馈。
- **互动真实性**：对“预设示例、浏览器计算、真实 AI 操作”采用明确文案，不靠颜色暗示。
- **键盘可达性**：支持焦点可见、Tab 导航，特别是 Chat/Agent 选项卡与可展开内容。
- **容错**：错误/空值给出明确原因，不静默生成一个“成功”结果。

### 7.3 讲师材料规范

每章至少应有：授课目标、建议时间、页面入口、讲师话术提纲、互动提问、预期现象、常见误区、真实账号演示指令、网络/权限失败的备用路径、收尾总结。

讲师模式可显示这些信息，但不向学员公布内部账号、现场网络、生产系统或未审核材料。

## 8. 技术与数据方案

### 8.1 V1.1 当前实现架构

- 根目录 index.html 为课程主站，包含原有 UI、内嵌案例和部分教学脚本。
- Prompt Lab 以独立 JavaScript 文件扩展：prompt-lab-m1.js、prompt-lab-m2.js。
- 独立 labs/ 采用 HTML + lab.css + 各专题 JS，尽量避免与主站全局变量耦合。
- scenario_data.json 作为 30 条原场景的可检查备份，主站内嵌数据与之保持严格一致。
- samples/ 存放虚构的 MES、采购订单、SOP、IE、IT 等教学输入。
- skills/sop-change-review/ 存放可阅读的 Skill 示例。
- examples/role-agent-mvp/ 存放两套离线 Python 原型。
- tests/ 存放静态、DOM 交互和 Python 测试；GitHub Actions 用于代码回归。
- 浏览器 localStorage 保存模式、教学勾选或进度，**不跨设备同步，不是学员后台**。
- 静态网站不存储 API Key、不发起企业系统写入，也不提供真实 AI API 调用。

### 8.2 建议的数据实体与归属

| 实体 | 稳定键 | 最小字段 | 数据归属 |
| --- | --- | --- | --- |
| CourseChapter | chapterId | title、order、route、minutes、teacherNotes | 课程配置 |
| PromptLesson | lessonId | module、title、steps、interactiveRules、refSource、checks | Prompt 模块 |
| BusinessScenario | case-XX | department、title、priority、prep、chatPrompt、agent、validation | 原 30 案 |
| RoleScenario | ie-XX / it-XX | title、inputs、chat、deliver、verify、risk | IE/IT 扩展 |
| AgentBlueprint | scenarioId | level、trigger、source、fields、tooling、steps[6]、failure、guard、acceptance | 独立岗位蓝图 |
| LabExercise | labId | task、sampleFiles、expected、checks、limitations | 专题实验室 |
| LocalProgress | namespace+version+id | completed、mode、selection | 仅浏览器 localStorage |
| AcceptanceCase | AC-ID | steps、expected、testFile、humanEvidence | 测试与发布流程 |

**数据治理要求**：教学基准数据应版本化；不要把真实客户、员工、供应商、产量、IP、故障日志等复制进公开仓库。展示案例扩展时须标识来源类型：“用户原表通用化需求 / 教学新增 / 模拟练习 / 真实已验证案例（仅有证据时）”。

### 8.3 前端与安全技术要求

- 不依赖外部 JS CDN 才能使用核心教学功能；离线下载需完整目录，不仅下载单文件 HTML。
- CSV 导入须检查必需列、重复、非法数字、缺失和特殊字符；导出须防 CSV 公式注入，保留编码兼容。
- 浏览器本地操作不应该发送企业数据至外部服务器；链接到第三方资料需要清晰的外链与隐私提示。
- 处理本地样例时尽量不修改源文件，导出新文件需区分输入、输出、异常记录。
- 不以硬编码模拟审批替代真实企业工作流。
- 日志/演示数据不得包含凭据、真实 IP、真实设备标识或内部敏感信息。
- 如果未来引入后端/模型连接，**必须另立独立架构评审**：身份鉴权、工作区权限、敏感数据脱敏、密钥托管、审计、成本限额、工具白名单、审批与回退；不能在静态站点直接放 API Key。

### 8.4 非功能需求

| ID | 指标 | 验收方式 |
| --- | --- | --- |
| NFR-01 | 桌面 Chrome/Edge 可用 | 最新企业允许版本实机点击主流程 |
| NFR-02 | 1920×1080 投影可读 | 讲师投影大字模式下人工检查 |
| NFR-03 | 375px 手机无关键遮挡 | 手机模拟器 + 至少一台实机 |
| NFR-04 | 教学主路径离线可用 | 断网打开完整 ZIP，验证全部本地实验室 |
| NFR-05 | 样例计算结果确定、可复算 | 与 CSV、脚本、预置正确答案比对 |
| NFR-06 | 键盘交互与焦点反馈 | Tab、方向键、Enter/Space 检查 |
| NFR-07 | 任务状态隔离 | 切换章节/案例不交叉写入错误状态 |

## 10. 关键用户旅程与端到端验收

### Journey A｜讲师 120 分钟完整授课

**前置条件**：整站 ZIP、浏览器、投影、讲师备份素材、企业合规测试账号（若需要真实演示）。

1. 打开首页，展示课程目标和时序。
2. 进入桌面端和 Enterprise 能力分工，说明真实账号与网页演练的边界。
3. 在 Prompt Lab 选择 M1 信息路径 + M2 一轮思考/验证。
4. 打开 MES 模拟数据练习，展示计算与核对；引出 Deep Research 或 M3。
5. 展示 Skill 的 SOP 文件结构与差异判断；简述 MCP/Plugin/CLI。
6. 在 Work 试做“公开资料对比”，做权限判断与模拟审批。
7. 在 Codex 运行 CSV 合并/检查与失败数据挑战，演示从需求到测试。
8. 展示两张高频 AI 技巧卡。
9. 进入部门案例，至少选一条 Chat 路线；必要时打开 IE/IT 的 Agent 蓝图。
10. 总结，给学员一份可带回岗位的练习任务。

**通过条件**：总时长可控、没有死链/白屏、模拟与真实演示不混淆、失败能切备份、最终每位学员都知道至少一个可立即尝试的合法任务。

### Journey B｜普通学员课后复现

1. 自学模式进入一个业务章节。
2. 下载模拟数据或使用已批准的个人/部门资料。
3. 复制简短 Prompt，在授权 ChatGPT 中实际执行。
4. 按参考答案/校验规则复核，记录证据或数据缺口。
5. 标记“已学”，自行保存输出，继续下一模块。

**通过条件**：脱离讲师仍可凭网页内容完成至少一个可重复任务；“已学”不伪装能力测验结果。

### Journey C｜IE/IT 学员理解 Chat→Agent

1. 打开 labs/roles.html#ie-01 或 #it-01。
2. 使用“阶段一：Chat 人工协作”下载虚构 CSV，照步骤运行/复制并对账。
3. 切换到“阶段二：Agent 流程自动化”。
4. 阅读触发器、只读数据源、必需字段、技术路线、六步流程、失败保护与人工审核。
5. 对照 Python 离线示例运行一次规则计算，得到输出/异常报告。
6. 列出本企业真正试点前还缺的数据接口、授权、阈值、运维支持和验收人。

**通过条件**：学员明确“Agent 是工作流设计，不是打开桌面版的另一种称呼”；不得跳过 IT 许可或直接操作设备。

### Journey D｜开发 Agent 修改一个教学模块

1. 先阅读本文和仓库 README、对应测试/验收单。
2. 列出关联 FR/AC、受影响文件与不能修改的范围。
3. 从 main 创建独立分支，先小范围实现与自测。
4. 运行原有及受影响的完整检查集。
5. 提交带截图/步骤/限制的 PR，等待讲师验收后合并。
6. 合并后再次检查主站 + Prompt M1/M2/M3 + 各实验室入口。

**通过条件**：没有覆盖并行窗口的模块，没有把“某一测试通过”当作全部质量保证。

1. 统一每个实验室的“老师说什么/学员做什么/预计输出/复核什么/异常怎么办”。
2. 在多部门案例中挑选 6–8 个具高复用价值的课堂标准案例，形成完整任务包；完整 30+12 案仍保留课后查阅。
3. 为 IE/IT Agent 案例补试点任务单、审批表、数据质量检查表和成果证据模板。
4. 增强 Skill/MCP/Plugin/CLI 的产品能力边界卡片，并随企业账号配置更新。
5. 整理参考答案、可复现输入与录屏资源，减少现场完全依赖网络或模型随机性。

### 13.3 V2.0 自学与游戏化（P2，建议，不改变讲师版）

- 按岗位设置新手/进阶/Agent 设计任务路径。
- 通过真实任务完成度、证据与复核清单展示学习进展；不只凭访问次数奖励。
- 任务可以包含选择题、排序、Prompt 迭代、CSV 异常修复、案例复盘。
- 暂不做跨人排名、正式成绩或带真实敏感数据的课后平台；若需要 LMS 后台须另评估鉴权、数据最小化和保留周期。

### 13.4 发布批次与代码治理

- 每个开发任务应记录：任务编号、关联 FR、源文件、测试文件、影响章节与演示截图。
- 有并行窗口时，Prompt Lab 和其他 labs 各自基于最新 main 建立独立分支，不覆盖对方模块。
- 不为了“让分支能合并”而删除已验收的内容；出现冲突先做内容级 diff，再共同解决。
- “本地可运行”“DOM 自动测试通过”“真实产品能力验收”“讲师验收”是不同状态，PR 描述必须逐项注明。
- 任何跨章节导航或页面共用样式修改，至少回归主站、M1/M2/M3、Research、Skill、Work、Codex 和 Roles。

## 14. 产品成功指标（建议设定，非当前既成事实）

| 维度 | 指标建议 | 采集方法 | 说明 |
| --- | --- | --- | --- |
| 授课可用性 | 主路径阻断错误 = 0 | 彩排问题清单 | 上线前硬门槛 |
| 时间管理 | 120 分钟内完成主线 | 讲师计时表 | 专题课后练习不强塞主线 |
| 操作复现 | 学员能独立完成 1 个模拟任务 | 课堂成果抽查 | 不只统计“已学”勾选 |
| 概念理解 | 能正确区分 Chat / Work / Codex / Agent | 课后情境小测 | 不预设结果百分比 |
| 业务可迁移 | 每个部门有可复用的真实工作任务单 | 部门反馈/实例复核 | 需合规与业务验收 |
| 内容可信 | 模拟/真实、结论/假设、来源/版本标识完整 | 内容审计 | 避免展示虚假“成功案例” |
| 后续开发 | 新改动有 FR/AC/测试/验收记录 | PR 审核 | 约束并行开发风险 |

不直接在静态网站收集个人行为或学员成绩；如未来确需统计，应先明确目的、权限、存储位置、隐私说明及授权。

## 15. 风险、依赖与待决策事项

| 编号 | 风险/不确定性 | 影响 | 处理方式 |
| --- | --- | --- | --- |
| R-01 | 真实企业账号不具备某项 Work/Computer Use/Plugin 能力 | 现场演示中断 | 提前彩排并准备可明确标注的备用教学材料 |
| R-02 | 模型每次生成的答案不同 | 课堂结果不可预测 | 准备标准输入、验证规则和“回答不正确也能教学”的路径 |
| R-03 | 静态教学流程被误解为实时 Agent | 误导学员和管理层 | 强制标注“演练/模拟/规则计算/真实执行” |
| R-04 | GitHub 仓库公开 | 内部场景/数据披露风险 | 发布清单、内容泛化、审查并清除敏感素材 |
| R-05 | 多窗口/分支并行开发 | Prompt 或其它功能被覆盖 | 文件隔离、PR diff 审阅、完整回归 |
| R-06 | 主站 120 分钟与专题深讲时间重复统计 | 正式课程超时 | 冻结精选脚本、专题作为按需或课后内容 |
| R-07 | 仅有 DOM 测试，没有设备/浏览器实测 | 实际展示失败 | 增加投影、手机、剪贴板、下载人工测试 |
| R-08 | 案例被当作生产系统方案 | 安全/质量问题 | 数据、审批、试点边界明确，真实接口另立项目 |
| R-09 | 技术/产品术语更新快 | 内容过时 | 内容标注最后核对日期，授课前复核官方文档 |
| R-10 | 学员能力分化大 | 新手跟不上、进阶学员无挑战 | 讲师版主线 + 进阶实验室 + 课后岗位路径 |

**待决策（不是开发阻断项）**：

- 是否将课后游戏化练习做成独立入口、独立站点还是同站第二模式。
- 正式授课版是否需要配套讲师 PDF/打印手册；核心教学仍以网页为主。
- 是否未来接入经过企业审批的 LMS 或真实 AI 服务；当前 V1.1 不需要。
- 是否公开全部 30+12 条通用化场景；发布前应以企业信息安全审核结果为准。
- 正式课程日期、参与人数、教室设备和企业账号授权状态，由讲师在彩排时确认。
