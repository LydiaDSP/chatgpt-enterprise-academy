## 0. 一页执行摘要

### 0.1 结论

项目已经从单页培训资料扩展为面向制造业多部门的静态交互教学平台，具备主站、Prompt M1/M2/M3、文件分析、Deep Research、Skill、Work/Computer Use、Codex、业务场景及IE/IT案例。现阶段的主要矛盾不再是课程数量不足，而是：

1. **授课主线没有统一**：主站与 M3 实验室分别描述120分钟路线，存在时间与内容编排不一致。
2. **模拟与真实实操存在断点**：可点击的教学模拟较完善，但真实企业账号演示、参考答案、业务验收尚未系统打通。
3. **主站与实验室没有统一教学状态**：讲师模式、投影模式、课程进度、返回路径各自实现。
4. **课程达成度判断偏弱**：标记“已学”不等于完成工作任务，更不能替代客观复核。
5. **工程与发布流程需要加强**：代码和数据源分散；现有CI主要以静态及DOM模拟为主；公开发布需要独立安全审查。

### 0.2 总体原则

- **先整合，再扩充**：未来三个开发批次不以增加新的课程模块或更多案例数量为主要目标。
- **授课版优先**：120分钟课程供讲师现场使用；深度练习作为课后自学，不将所有实验室完整内容塞进课堂。
- **真实、模拟、设想必须分清**：浏览器本地JS工具、预制参考结果、真实AI工具运行结果、未来Agent方案分别标识。
- **保留已验收成果**：不推倒重写，不擅自改动30条原始业务场景和12条IE/IT扩展案例的含义与来源。
- **静态优先**：当前不引入后端、账号体系、模型API或企业系统连接；确有必要再另立项目评估。
- **每批独立分支—自动测试—人工验收—再合并**；多个开发窗口不得同时无协调修改主站同一区域。

## 1. 项目目标、用户与边界

### 1.1 项目目标

构建一套**制造业多部门企业版ChatGPT互动教学平台**，帮助同事从“了解AI功能”成长为“能够对真实业务问题选择工具、独立执行、检查结果、复用方案”的实践者。

平台同时服务两种场景：

- **讲师现场授课**：固定120分钟核心路线，讲师能够顺畅展示、自由跳转、投屏、管理演示风险，并引导学员完成关键操作。
- **学员课后自学**：按能力逐级练习，结合岗位选择任务，以可检查的成果而不是点击次数判断完成情况。

### 1.2 覆盖对象

原有业务场景六部门：财务（FIN）、研发（RD）、品保（QA）、供应链（SCM）、制造（MFG）、人资（HR）；扩展：IE、IT。

**不是**为八个岗位分别制作八套完整课程；应采取“统一AI能力主线 + 岗位练习包 + 分层难度”的设计。

### 1.3 关键边界

1. 站点是静态教学网站，不会直接操作ChatGPT/Work/Codex、控制浏览器/电脑、连接ERP/MES/PLC或读取企业内部数据。
2. 浏览器本地运行的CSV检查程序是可执行JS示例，不等于真实模型执行。
3. IE/IT的Agent方案属于教学实施蓝图，不代表公司已部署或具备接口权限。
4. 练习素材应使用虚构、公开或者正式授权且已脱敏的数据。
5. 浏览器本地进度只保存在本设备，不能宣传为企业学习管理系统或跨设备同步。
6. 正式授课涉及的产品功能可见性，应在实际Enterprise测试账号和管理员配置下逐项确认。

### 1.4 暂不纳入本轮

- 不建设登录、云端学员档案、班级成绩管理、证书系统或排行榜服务。
- 不为教学网页接入真实模型API密钥、内部数据库、企业微信或业务审批接口。
- 不扩充到100个案例；先修复已有案例的教学质量与可复现性。
- 不为重构而迁移至大型前端框架；只有当现有结构阻碍交付时才评估。

## 4. 建议的统一课程信息架构

### 4.1 单一教学主线

课程按“了解能力 → 与AI协作 → 搜索/数据 → 执行/构建 → 岗位迁移”的顺序推进：

1. **能力与治理**：Chat、Work、Codex，企业数据/权限边界。
2. **Prompt M1/M2**：直接提出任务、提供上下文、脑暴、客观评价、渐进写作。
3. **Research**：信息获取、来源核查、证据可信度与Deep Research适用条件。
4. **多模态与数据 M3**：图片事实/推断、图片生成任务设计、文件数据统计与复核。
5. **Skill/MCP/Plugin/CLI**：方法复用、连接、现成能力、命令行；仅理解使用场景，非全员开发课。
6. **Work/Computer Use**：多步骤工作、浏览器/电脑操作边界与人工审批。
7. **Codex / 应用构建**：将明确的Goal/Input/Output转为可运行、可测试工具。
8. **岗位综合实践**：从30+12个场景中挑选适合个人的练习题并交付。

### 4.2 120分钟唯一建议路线（待讲师彩排确认）

| 时间 | 时长 | 核心课堂内容 | 形式 | 课堂可验证产物 |
| --- | ---: | --- | --- | --- |
| 00–08 | 8分钟 | 开场、学习目标、企业信息安全规则 | 引导 | 明确一个自己想解决的业务问题 |
| 08–18 | 10分钟 | Chat/Work/Codex及企业权限 | 讲师演示与判断 | 3个任务的工具选择判断 |
| 18–38 | 20分钟 | Prompt M1/M2：上下文、迭代、Rubric | 互动+复制真实指令 | 一条完整任务指令及1次修正 |
| 38–50 | 12分钟 | Search/Deep Research的证据核查 | 讲师演示+互动 | 来源可信度判断及研究任务单 |
| 50–65 | 15分钟 | 图片/文件/数据M3、MES结果复核 | 示例+学员检查 | 一张指标表及核验结论 |
| 65–75 | 10分钟 | Skill/MCP/Plugin/CLI全景和SOP示例 | 示范 | 判定哪些步骤值得沉淀Skill |
| 75–90 | 15分钟 | Work任务分解、权限与人工批准 | 演示+决策实验 | 任务计划、审批节点和风险判断 |
| 90–107 | 17分钟 | Codex从需求到运行、测试、修复 | 讲师真实演示或备用录屏 | CSV处理结果、异常清单、测试结论 |
| 107–117 | 10分钟 | 根据岗位选择一个案例并规划首轮操作 | 小组/个人练习 | 第一项AI业务任务卡 |
| 117–120 | 3分钟 | 复盘、课后实践与反馈 | 总结 | 学员知道下一步提交什么成果 |
| **合计** | **120分钟** | | | |

**安排规则**
- M3完整五节、Research完整报告、Skill安装、Codex从零开发全部留作扩展课；课堂选择代表性环节。
- 某种企业功能不可用时，按预备的“预制步骤/录屏+结果复核”替换，但标注为备用展示，不声称实时执行。
- 主站与Lab必须从同一课程路线配置读取章节名称、时长和入口；如不能立即共用代码，也应建立唯一权威配置并通过测试防止重复时间表。
- 本表是**建议排课方案**，须经过完整彩排和真实学员试讲才能定稿。

### 4.3 讲师模式与自学模式的区别

| 维度 | 讲师模式 | 自学模式 |
| --- | --- | --- |
| 核心目标 | 现场稳定讲授，形成共同认知 | 不依赖讲师完成微任务 |
| 路线 | 120分钟固定主线，可自由跳 | 按能力水平或岗位任务进入 |
| 页面元素 | 计时、讲师备注、标准结果、课堂问题、备用入口 | 任务说明、数据下载、尝试区、反馈、结果对照 |
| 答案展示 | 讲师可直接查看讲解材料 | 鼓励先作答再展示标准解释 |
| 进度 | 当前讲授节点、已演示内容 | 练习是否尝试/复核/验收 |
| 互动 | 全班讨论、投屏点击、现场提问 | 独立作答、可重试、可导出 |
| 跳转限制 | 不限制，保证授课灵活 | 推荐路径但不强制锁章节 |
| 安全 | 现场只使用授权的模拟或测试数据 | 默认虚构素材，不向网页上传真实企业数据 |

**模式技术要求**：定义统一的模式键和投屏键，进入实验室时继承状态；实验室返回主站时记住来源章节（仅本地存储或URL参数，不上传服务端）；不能把包含个人练习数据的URL意外暴露。

### 4.4 学习闭环（所有重点练习统一）

每项重点任务采用以下结构：

1. 业务问题：描述具体工作目标、适用人群与不适用范围。
2. 输入材料：文件模板、字段说明、数据来源及是否虚构。
3. 操作：网页教学动作 + 在经批准的Chat/Work/Codex中执行的真实指令。
4. 参考结果：正确输出片段或期望计算值，并明确“预制参考”或“实时运行”。
5. 常见失败：至少一个误判、空值、权限不足或数据格式异常。
6. 验收：量化的检查表、抽样复算或证据复核，禁止只用“感觉不错”。
7. 迁移：替换为本部门授权资料时，应修改哪些字段、补哪些规则。

## 6. 第五批 V1.3｜实战任务包、评价和讲师彩排

### 6.1 目标

从“看懂可点击页面”升级为“能在授权环境执行任务并拿到可核验成果”。不要求网页自己连接AI服务。

### 6.2 四套必须交付的标准任务包

#### TASK-01 Prompt协作与Rubric

- 场景：品保异常记录的初步分类与问题汇总。
- 输入：虚构的异常描述和少量结构化记录。
- 操作：短指令→补充背景→客观评价→改进输出。
- 输出：异常摘要、事实与推断分离、待核实项。
- 验收：不得虚构根因；关键事实能找到原始记录；Rubric含完整性/证据/可执行性/风险四维。
- 失败样例：一上来就要求“证明这个方案最好”、把相关性直接写成因果。

#### TASK-02 文件与数据复核

- 场景：模拟MES生产日报统计。
- 输入：现有模拟CSV，附字段字典和标准指标口径。
- 操作：检查数据→计算产量/达成率/直通率→抽样复算→解释异常。
- 输出：按产线的指标表、异常清单、简短管理摘要。
- 验收：关键数字与脚本/人工复算一致；缺失值、重复值和分母为零情况须明确处理。
- 失败样例：简单平均分组百分比、混淆投入与合格口径、将趋势描述成已证实根因。

#### TASK-03 Work任务与审批边界

- 场景：三家公开物流服务商信息对比，或经批准的公开资料研究。
- 输入：公开网站清单、任务目标、禁止外发/写入的限制。
- 操作：选择Chat/Research/Work→规划步骤→收集来源→生成对比→人工检查。
- 输出：附来源的比较表、待核实清单、操作与审批记录。
- 验收：至少抽查3条关键结论的来源；未授权动作必须暂停，不允许模拟批准替代真实批准。
- 失败样例：引用不可访问网页为证据、擅自提交表单或向外部发送材料。

#### TASK-04 Codex构建与测试

- 场景：多份模拟采购订单CSV合并与异常校验。
- 输入：已有3份模拟CSV、字段说明、重复键与校验规则。
- 操作：Goal/Input/Output需求单→让Codex实现→运行测试→发现错误→修复。
- 输出：合并结果、异常清单、可执行工具、README或操作说明。
- 验收：行数准确、按订单号+料号识别重复、日期/数量异常正确识别、不覆盖原文件；至少正常/异常各1例。
- 失败样例：只能展示生成代码而不能运行、未测异常输入、CSV公式注入风险未处理。

### 6.3 每个任务包应具有的文件结构（建议）

- 任务说明：学习目标、准备环境、许可与禁止事项。
- 模拟数据：原始输入及说明。
- 讲师脚本：逐步演示操作、提问时机、课堂时间。
- 学员练习卡：在授权AI工具中可直接使用的最短起始指令与迭代提示。
- 参考答案：预期结果与计算口径；必须标注为预制。
- 验收Rubric：可观察、可复核、可追溯的评分标准。
- 故障备选：若实时账号或网络不可用，如何展示录屏/截图并继续讲解。
- 安全声明：无未经批准的生产数据、账号凭据或生产系统写入。

### 6.4 成果分层

- **浏览**：进入页面并理解目标，不代表完成任务。
- **尝试**：提交了答案/完成了操作，但未核验。
- **自检通过**：完成本地规则检查、标准结果复核。
- **讲师/同事复核**：基于实际交付物、数据与证据的外部确认。

不建议仅凭点击“完成”直接赋予“通过”状态。前端本地可保存状态与非敏感自评；真实成果由学员按企业规定途径提交，不经公开Pages站点收集。

### 6.5 Rubric统一建议（共100分，可按任务细化）

| 维度 | 建议分值 | 判断方法 |
| --- | ---: | --- |
| 任务目标与约束 | 20 | 输入/输出、权限、业务范围是否明确 |
| 数据与证据准确性 | 30 | 数字复算、引用可溯源、事实与推断分离 |
| 可执行性与交付质量 | 25 | 产物可使用、步骤可复现、格式符合要求 |
| 异常与安全边界 | 15 | 缺失/错误/越权是否被识别并正确处理 |
| 复盘与改进 | 10 | 能指出失败原因并进行一次有依据的迭代 |

建议合格线：80分且“数据与证据准确性”“安全边界”无关键失误。此为拟议培训规则，须通过试讲再确认。

### 6.6 彩排与课前门禁

- 企业账号检查：Chat、Search、Deep Research、Work、Codex、Skill、Plugin、Browser/Computer Use，逐一记录是否可用及限制。
- 网络/登录检查：外部网页、官方资源、文件上传下载、浏览器弹窗权限。
- 课堂完整彩排：严格按120分钟路线计时，不仅是单页点验。
- 失败准备：至少4个核心任务有录屏/截图备用；敏感画面先脱敏，不把内部录屏上传公开仓库。
- 试讲抽样：至少邀请不同岗位、不同AI熟练度的学员试用，并记录卡点与完成时间。
- 完成标准：4套任务包可复现；讲师能解释每处模拟/真实边界；至少一次完整授课彩排有记录。

## 7. 第六批 V1.4｜工程质量、视觉与发布

### 7.1 渐进模块化

优先从最易变动的共享部分入手：

1. 课程路由/课表配置：单一来源，避免重复维护。

**注意**：静态file://访问下使用fetch读取JSON存在跨浏览器限制；不能直接把当前内嵌场景改为运行时fetch而破坏离线使用。优先采用构建时生成或其他无需服务端的静态装配方式。

### 7.2 本地状态统一

建议采用命名空间及版本：课程模式、字体偏好、各任务进度、个人练习草稿分别存储；提供兼容旧记录的迁移/容错逻辑。

必须区分：
- 课程浏览进度；
- 自检结果；
- 讲师确认状态（仅外部记录，不可伪造为正式系统签发）；
- 个别任务的临时草稿。

localStorage容量不足、禁用或损坏时要提供清晰提示，不应导致页面崩溃；敏感企业数据禁止默认持久化到公共教学网页。

### 7.3 浏览器E2E与可访问性

建议采用Playwright覆盖代表性的完整用户旅程，而不只检查DOM存在性：

- 首页→Prompt→M3→返回；模式、页内定位和进度一致；
- Files加载模拟CSV并得到预期指标；
- Work走完权限题/审批模拟/重置；
- Codex执行正常及异常CSV数据、下载结果；
- IE/IT案例Chat与Agent切换互斥、键盘箭头导航正常；
- 移动端菜单打开、关闭和滚动行为；
- 大字模式的内容可读性与按钮可点击性。

浏览器矩阵建议：
- Chrome（桌面，标准1280×800、投影1920×1080）；
- Edge（桌面）；
- 手机竖屏375px及390px；
- 条件允许时补充Safari/macOS和移动Safari。

人工可访问性抽验：
- 页面可按Tab顺序使用；
- 焦点明显；
- 所有非装饰按钮有名称；
- 选项卡使用正确aria状态；
- 错误提示能被理解，不能只靠颜色区分；
- 大字与缩放后不截断重要内容。

### 7.4 CI、代码审查和发布机制

建议改进 .github/workflows/acceptance.yml：
- push覆盖main和实际开发分支模式；
- pull_request仍按代码/样本/测试/关键文档变化触发；
- 重要任务通过后才允许合并；
- jsdom只承担快速冒烟，Playwright单独执行核心E2E；
- 测试依赖做可复现锁定，避免每次动态安装相同范围包导致差异；
- 主分支发布前记录Git commit SHA、测试结论、发布日期和维护人；
- 文档更新可以走轻量检查，但变更课程配置须运行完整课程一致性校验。

发布门禁：
1. 内容安全许可已取得。
2. 仓库扫描确认没有真实账号、Token、患者/员工/客户敏感信息、内部地址等。
3. 学习素材均可被允许公开展示。
4. Pages实际站点可以访问，链接和相对路径正确。
5. Chrome/Edge/移动端/投屏已按清单检查。
6. 模拟功能均贴有准确标识；真实功能仅在被授权账号中演示。
7. 主线授课彩排与课程负责人验收记录齐全。

### 7.5 公开仓库安全注意

本仓库目前是Public。原30条场景包含内部盘点标题和优先级的教学改写；上传公开仓库前应按公司规定完成内容审查。即便不包含附件原始Excel，也不能据此自动认定允许公开。

明确禁止上传：原始业务盘点表、未授权内部SOP/设备日志、真实MES数据、员工/患者信息、登录截图/口令、Token、企业专用域名和其他不允许公开的材料。

如发现未经授权公开内容：停止传播，先隔离公开访问并通知责任人；仅从最新提交删除文件可能不能消除Git历史中的敏感数据，必须按信息安全要求处理历史和缓存。

## 8. 岗位案例统一设计规范

### 8.1 案例来源

- **原始30案**：来自已提供业务需求盘点，保持数量、部门、来源、原顺序及原优先级，不将其写成企业已落地成果。
- **扩展12案**：IE与IT新增教学案例，保留“教学新增”标识及各自独立的Chat/Agent两阶段。
- 如需新增案例，另建清单并标记来源；不能无提示混入原始30案。

### 8.2 所有主推案例使用统一字段

| 字段 | 说明 |
| --- | --- |
| 场景ID/岗位/来源 | 唯一ID、归属、原始盘点或教学扩展 |
| 业务问题及目标 | 想解决什么、期望节约什么或改善什么 |
| 前置材料 | 样例文件、字段、授权需求、前提条件 |
| Chat阶段 | 用户怎样手动准备文件、在Chat中输入什么、怎样追问 |
| Chat输出和验收 | 产物格式、必须复核的数字/证据、常见失败 |
| Agent阶段 | 触发条件、读取接口/文件、步骤、日志、异常、审批 |
| 试点MVP | 最小先做什么、是否只读、需要谁配合 |
| 安全与限制 | 不得自动写入/删除/配置生产系统的边界 |
| 复用材料 | 指令、Skill、脚本或GitHub链接（如有） |
| 成熟度 | 需求构想/本地原型/授权试点/已上线；不得推测 |

### 8.3 案例模板：IE标准工时/节拍复核（教学示例）

- Chat：导入虚构的工序时测CSV；确认单位、样本量和测量条件；按工序复算目标与实测差异；列出需要复测的工位。
- Agent：由已获批准的数据源按计划触发；只读获取字段；检查格式与重复；调用规则/脚本计算；生成待审报告；提交IE负责人核验。
- 异常：缺失单位、测量条件不一致、数据过旧、重复样本时标记而不是自动发布结论。
- 验收：随机抽样3个工序复算，确认计算口径及异常处理；未经批准不修改工艺标准。

### 8.4 案例模板：IT设备在线事件复核（教学示例）

- Chat：用虚构在线事件CSV对照时间、设备标识、断连与恢复配对，识别持续未恢复事件。
- Agent：从只读事件导出或授权API获取数据；配对并去重；超时阈值经IT确认；生成待确认工单草稿。
- 异常：同一设备重复报警、事件乱序、丢失恢复事件或时间格式错误。
- 安全：不自动登录修改WinCC、TIA Portal、网关、网络设备或生产控制参数。
- 验收：用已知模拟用例检查配对、重复、超时边界和人工确认状态。

## 10. 质量指标与效果衡量

以下是**建议验收目标，不是当前项目的实测成绩**。

### 10.1 交付质量

| 指标 | 拟议目标 | 证据 |
| --- | --- | --- |
| 核心教学路线完整性 | 120分钟，章节时长合计正确，无冲突课表 | 课程配置与静态测试 |
| 关键功能回归 | 原有核心测试全部通过 | CI运行记录 |
| Lab跨页面闭环 | 4条代表性主路径全部可往返 | 浏览器E2E |
| 案例覆盖 | 原30案、扩展12案完整可访问且标识不混淆 | 数据一致性测试 |
| 核心真实任务包 | 至少4套完整任务 | 文件、结果、Rubric与彩排记录 |
| 公共安全审核 | 正式发布前100%完成 | 审核记录 |
| 讲师彩排 | 至少1次120分钟全程彩排 | 时间记录与修复清单 |

### 10.2 教学效果

| 指标 | 采集方式 | 首轮拟议目标 |
| --- | --- | --- |
| 课堂任务独立完成率 | 在授权测试环境观察独立完成情况 | 主推练习 ≥80% |
| 数据/证据核验正确率 | 与参考结果抽查对比 | ≥85% |
| 关键权限判断正确率 | Work审批决策题 | ≥90% |
| 课后岗位迁移率 | 学员提交第一项真实或授权模拟任务 | 首批试讲后再定基线 |
| 讲师超时次数 | 120分钟彩排计时 | 核心段无严重超时 |
| 操作卡点数 | 记录无法定位入口、无法返回、看不懂操作的情形 | 每次迭代持续下降 |

先做小规模试讲收集基线，不建议直接把拟议数字作为硬性绩效考核。

## 11. 风险与应对

| 风险 | 触发情形 | 防范策略 | 回退 |
| --- | --- | --- | --- |
| 跨窗口合并冲突 | Prompt/Work/主站并行开发 | 文件修改归属与分批PR | 停止合并，基于最新main重放必要变更 |
| 离线功能损坏 | 静态站改为运行时读取JSON | 保留file://模式测试 | 恢复上一版嵌入式/预构建数据 |
| 真实账号功能不一致 | 管理员权限或版本不同 | 课前权限表，提供替代任务 | 用预制录屏和本地练习 |
| 课堂时间失控 | 实操过多、网络阻塞 | 固定主线与计时，课后深度实验 | 直接进入参考结果与复核 |
| 模拟被误认为真实AI | JS工具或预制内容没有标注 | 全站显式标签与说明 | 禁止对外描述为已接入AI |
| 数据泄露 | 上传内部素材至Public仓库 | 发布前审核，禁止上传原始企业资料 | 隔离公开访问并按安全流程处理 |
| 自评虚高 | 只点击“完成” | 产物证据 + Rubric + 抽样复核 | 调整状态为“已浏览/待核验” |
| 浏览器兼容性 | 手机、Edge、Safari或file://差异 | E2E + 人工抽验 | 恢复原功能或提供兼容提示 |

## 12. 每批共用Definition of Done（完成标准）

一个开发批次达到“代码可合并”，至少需满足：

- [ ] 已在独立分支完成全部承诺范围，未混入另一窗口正在开发的功能。
- [ ] 修改前后差异、受影响页面、数据和权限边界都有记录。
- [ ] 现有30+12案例及已验收的Prompt、Research、Skill、Work、Codex能力没有意外回归。
- [ ] 自动测试通过，测试覆盖新增交互及错误输入。
- [ ] Chrome/Edge完成关键路径人工验证，投影/移动端缺失项明确列为未完成。
- [ ] 未出现把本地模拟误写成真实AI或Agent执行的文案。
- [ ] 无未经许可公开的信息，安全审核意见保留。
- [ ] PR附有验收步骤、测试结果、已知问题和明确回退策略。
- [ ] 课程负责人确认验收，才允许合并main。
- [ ] 合并后再次验证main与线上部署版本；不能只根据PR合并成功推断发布成功。
